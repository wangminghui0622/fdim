## 数据流程验证

### 已读回执流程
```
1. 用户B进入聊天页面
   ↓
2. 调用 markConversationMessageAsRead(conversationID)
   ↓
3. 后端处理并发送通知给用户A
   {
     contentType: 1400,
     content: {
       markAsReadUserID: "B",
       conversationID: "si_A_B",
       seqs: [1, 2, 3],
       hasReadSeq: 3
     }
   }
   ↓
4. 用户A的SDK接收通知
   - 解析 ReadReceiptInfo
   - 触发 recvC2CReadReceipt([info])
   ↓
5. 用户A的聊天页面处理
   - 检查 userID == "B" ✓
   - 遍历消息，匹配 seq in [1,2,3]
   - 设置 isRead = true
   - 触发 setState()
   ↓
6. UI 更新显示"已读"
```

## 故障排查

### 如果"已读"不显示

1. **检查后端日志**：
   ```
   搜索: "Sending HasReadReceipt notification"
   应该看到: fromUserID=B, toUserID=A, seqs=[1,2,3]
   ```

2. **检查前端SDK日志**：
   ```
   搜索: "[SDK] 【DEBUG】Received HasReadReceipt notification"
   应该看到: HasReadReceipt detail: {markAsReadUserID: B, ...}
   ```

3. **检查前端UI日志**：
   ```
   搜索: "[Chat] Received read receipt"
   应该看到: conversationID=si_A_B, hasReadSeq=X
   ```

4. **检查数据匹配**：
   - `readInfo.userID` 是否等于 `userID`？
   - `readInfo.seqs` 是否包含消息的 `seq`？
   - 消息的 `sendID` 是否等于当前用户ID？

### 如果未读数不清零

1. **检查后端日志**：
   ```
   搜索: "Sending ConversationUnreadChange notification"
   应该看到: userID=B, conversationID=si_A_B, unreadCount=0
   ```

2. **检查前端SDK日志**：
   ```
   搜索: "[SDK] 【DEBUG】Conversation notification received, contentType=1702"
   ```

3. **检查会话列表日志**：
   ```
   搜索: "[ConversationPage] 【DEBUG】conversationChangedSubject triggered"
   ```

4. **检查服务器返回数据**：
   - 会话列表API返回的 `unreadCount` 是否为0？
   - 如果不是0，说明后端未正确更新
